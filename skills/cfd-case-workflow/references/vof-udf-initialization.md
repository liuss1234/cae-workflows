# QFlux VOF 与 UDF 初始相

## 适用场景

用于熔融锡膏、液滴、润湿铺展等初始自由液面问题。核心目标是把若干离散液体体积定义为同一个流体 Region 内的初始次相体积分数，而不是把每个液体块拆成独立 Region。本流程只处理初始相和求解启动；刚体运动、动态网格、接触和完整瞬态仍需按案例参数单独配置与验收。

## 建模原则

1. 空气与液相共享同一个流体 Region；液体块是该 Region 中 `alpha_liquid=1` 的初始分布，外部空气由 `1-alpha_liquid` 得到。
2. CAD 实体、初始相轮廓与求解 Region 是三个不同概念。CAD 中可以有多个命名实体，但导入求解器后不应因此自动生成多个流体 Region。
3. 轴对齐包围盒（AABB）只能表示矩形投影。带圆弧、圆角、缺口或 U 形的初始体积若用 AABB，会把真实轮廓外部也填成液体；必须先计算多填体积，再决定是否可接受。
4. 优先从 STEP 中按稳定名称或几何规则提取每个液体实体的底面真实外轮廓。曲线离散使用明确的最大弦高，并保存原始连续几何体积、离散多边形体积和误差。
5. UDF 通常按单元中心 `(x,y,z)` 判断点是否位于任一平面轮廓及其厚度范围内，只写液相体积分数字段。不要同时独立写空气相，避免两相体积分数不守恒。

## 从 STEP 轮廓生成 UDF

推荐流程：

1. 独立回读 STEP，确认实体数量、名称、坐标单位、底面高度和厚度。
2. 对每个实体选择与基板平行的底面，提取闭合外环；若存在内环，必须作为孔洞处理，不能只取外包络。
3. 直线保留端点；圆弧、样条按最大弦高离散。对微米级焊料轮廓，可从 `0.1 um` 弦高开始，并根据连续体积误差调整。
4. 计算 `连续 CAD 体积`、`离散轮廓面积 x 厚度` 和相对误差。该误差反映轮廓离散，不包含网格单元中心选取误差。
5. 生成只依赖数值数组和点包含判断的 UDF；运行时不再依赖 CAD 内核。源文件、编译依赖说明和生成脚本均应随源码包交付。
6. 编译后把主 UDF DLL 及其运行时依赖放在案例根目录下的 `udf/lib/`。在目标电脑先检查 DLL 位数、编译器 ABI 和依赖是否与 QFlux/QSolver 匹配。

概念性判断如下，字段名必须以目标版本实际声明为准：

```text
if z_min <= cell_center.z <= z_max and point_in_any_profile(cell_center.x, cell_center.y):
    vof-liquid = 1
else:
    vof-liquid = 0
```

不要把这段伪代码直接当作特定版本可编译 UDF。应从本机头文件和示例确认函数签名、字段访问器、线程/分区行为及并行安全性。

## 误差分层

至少分开报告三类误差：

| 层级 | 对比对象 | 说明 |
|---|---|---|
| 包围盒误差 | AABB 体积 vs. STEP 真实体积 | 反映几何方法是否错误；不能靠加密网格消除 |
| 轮廓离散误差 | 多边形体积 vs. STEP 真实体积 | 由弦高、曲线离散和孔洞处理决定 |
| 网格初始化误差 | 选中单元体积 vs. 离散轮廓体积 | 由单元尺度、中心点判定和边界切割决定 |

轮廓离散很精确并不保证网格初始化体积同样精确。验收时应导出或统计被赋值单元数与总体积；必要时在自由液面、窄间隙和曲率变化处局部加密。

## 物理设置核对

以焊料润湿为例，至少回读：两相密度和黏度、重力方向、层流/湍流选择、CSF 表面张力系数、各材料壁面的静态/动态接触角、压力出口/对称边界，以及液相初始字段。不同材料壁面必须按表面组分别赋接触角，不能用一个全局角度覆盖铜、元件和阻焊面。

若启用 DFBI、Morphing 或接触约束，还需提供并回读刚体质量、质心、惯量、自由度、初始姿态、接触间隙和约束。缺少这些数据时只能完成固定壁面的 VOF/UDF 烟雾测试；不得用软件默认质量或惯量冒充运动设置已完成。

## 启动与单步验收

QSolver 会回写 `-q` 指定的工程。每次运行先复制源 QFX 到新的阶段目录：

```powershell
Copy-Item final.qfx runs/<stage>/solver_input.qfx
```

通过 MCP/API 启动含 UDF 的案例时，先查目标版本 `QSolverParameter` 声明。除 `qfxFile`、输出目录、核数等字段外，必须把案例根目录传给 `sPath`，使实际命令包含：

```text
--spath <case-root>
```

否则求解器可能找不到 `udf/lib/` 中的主 DLL 或运行时依赖。先做 1 个瞬态步、1 次内迭代的烟雾测试，检查：

- 求解器进程正常结束，日志包含核心完成标记，而非仅有启动成功；
- 生成的步 1 DAT 明显不是空文件或初始 DAT，并可由官方 API 回读；
- 液相字段存在，初始液体体积与审计值在预定容差内；
- UDF 已被实际加载，没有 DLL 缺失、位数、符号或并行加载错误；
- QFX、初始 DAT、步 1 DAT 和日志记录 SHA-256，阶段目录不覆盖历史结果。

日志中的自动路径修复提示需要结合后续完成标记和完整 DAT 判断，不能只凭单行 `check case error` 判定失败。反过来，单步成功也只证明链路与 UDF 可运行，不证明完整瞬态收敛、润湿/融合结果正确或刚体自对准有效。

## 可迁移交付

运行包保留 QFX、单步输入副本、`udf/lib/`、UDF 源码、检查 JSON、说明和哈希；源码包再加入 STEP/MSH 与相对路径重建脚本；大体积 DAT 和日志放独立结果包。生成脚本只使用包内相对路径或接收本机 `environment.local.json`，不得固化开发机的 STEP、运行时、宿主 ID 或安装目录。
