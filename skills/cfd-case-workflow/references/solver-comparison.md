# 跨求解器与原生后处理

## 调用方式按真实链路描述

| 软件/通道 | 可用方式与说明 |
|---|---|
| FreeCAD | 官方 Python/宏与 OCC 操作；GUI 宏可在软件中显示建模过程。后台建模不等于实时点击GUI |
| Gmsh | Python API/命令行；Physical Groups 和单元/边界表必须实际导出并回读 |
| QFLUX Windows | 目标发行版官方 Python API，通常需对应 Python ABI 与 DLL 环境；使用独立进程隔离库冲突 |
| QFLUX Linux | 现场已验证的 uiToCore、partition、MPI qcore Slurm 链路，参数以版本为准 |
| STAR-CCM+ | 版本匹配的 Java 宏/批处理与原生场景渲染；先验证安装、许可和最小读写 |
| Fluent | 对应版本 journal/TUI/PyFluent 等官方入口；先验证版本、许可、网格区与求解设置回读 |
| MCP | 工具调用通道；只有实际存在可调用 server/tool 且返回有效结果时才称 MCP 调用。API/宏不因由智能体启动就成为MCP |

不要把用户曾要求 STAR/Fluent 对比写成已完成三软件端到端验证。缺少真实运行证据时说明状态；用户停止某软件对比即停止该分支。

## 跨求解器比较的准入门槛

对比前逐个求解器验收，不能因使用同一份网格或相同迭代数就默认结果有效、物理设置等价。建议按以下顺序核对并保存证据：

1. 回读各软件实际使用的几何/网格、单位、区域与边界映射、旋转轴和转速、材料、参考压力、湍流模型子类型、近壁处理、离散格式和求解控制。仅有设置脚本或输入文件不代表设置已生效。
2. 分别报告每个有效方程的原生残差判据及末值/历史，连续性与能量等守恒误差，以及工程监控量的稳定窗口。残差定义可能是绝对值或相对值、归一化方式也可能不同；保留软件原始判据，不把未达标的结果通过放宽门槛变为“收敛”。
3. 统一比较量的定义和采样口径：截面坐标、法向、积分方向、静压/总压、绝对/相对速度、质量/面积/体积加权方法和单位。点值应使用相同 XYZ 坐标；记录采样是求解器原生点采样、面上插值或最近单元值，并保留坐标和插值来源。
4. 检查结果的物理合理性，包括正负方向、量级、局部极值位置、质量/能量收支和预期尺度。出现发散、异常峰值或守恒失败时，结果只可标作诊断数据，不纳入有效性能排序或软件准确性结论。
5. 只有各软件工况分别通过预先说明的数值与工程验收门槛后，才汇总跨软件差异。模型实现、壁面处理、网格质量或收敛水平不等价时，将它们列为限制，不把差异归因于单一设置，除非有受控单因素证据。

## 计算口径

固定源几何版本、单位 m、域/边界映射、物性温度、总流量、压力基准、模型子类型、壁面处理与离散格式。网格不一致时记录单元类型、单元数和近壁策略；求解器 KW 不能仅凭名称当 SST。

多支路流量使用同义截面和方向的有符号积分；汇总守恒、各路流量及偏差/CV。压降固定静压或总压、平均方式和截面；差异定义 `Δ=A−B`，相对差按指定基准 `Δ/B×100%`，基准接近0时仅给绝对差，不能称无独立真值的差异为“准确率”。分别展示残差、质量守恒和稳定性；正常退出不代表结果可比。表格和图中明确标注未通过验收的求解器结果为诊断数据，并从有效结果统计中排除。

## 原生云图与视图控制

用户要求两个软件各自生成云图时，在各自软件的原生后处理器创建场景、截面、变量、图例和截图。可以用 Python/Java 驱动官方 API，但不得把外部 Python 绘图冒充求解器原生云图。只有导出了真实图片且检查成功才称已导出。

同物理量比较统一：坐标系、截面位置、相机方向/上方向/投影/缩放、变量与分量、绝对/相对速度、压力基准、节点/单元显示、单位、色标上下限与图例。优先用API设置相机而非反复截图；API无法设置时明确限制与下一种可用方式，不能声称视角一致。保留各软件场景/宏及原始图片用于复现。

PPT/报告保留工况、单位、色标和来源；物理量不同或无统一色标依据时分开展示，不补造数据。
