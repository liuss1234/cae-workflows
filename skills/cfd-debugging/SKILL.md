# CFD 调试经验

把「跑不通」的求解定位到具体原因并给出可验证的修复，而不是靠反复调参数碰运气。适用于已经建立网格和工程、但求解发散、残差不降、守恒失衡、负量或结果物理异常的案例；建模、网格和交付阶段仍由各自的技能负责。

## 先做三件事

1. 保留证据：记录网格/QFX/DAT 的哈希、实际求解设置、起止步、残差曲线、监测点历史、守恒量和最后一份完整产物。失败阶段单独保留，不覆盖成功网格。
2. 确定失败阶段：读实际日志和最后完整步，区分「网格导入失败」「首步即爆」「跑几步后发散」「残差停滞」「能跑完但结果不合理」，不要把所有异常都当成发散处理。
3. 一次只改一个量：先回读确认当前工程真的加载了预期设置（不是旧 QFX），再单因素试验；同时改多个量只能算组合试验，不能宣称定位到单一原因。

## 按现象路由

| 现象 | 阅读 |
|---|---|
| NaN、负压力/温度/密度、速度或湍流量超限、首步即爆 | [发散诊断](references/divergence.md) |
| 残差停滞不降、来回振荡、守恒量失衡、监测量长期漂移 | [收敛异常](references/convergence.md) |
| 负体积、高非正交/偏斜、边界层塌陷或缺失、单位或包围盒不对 | [网格质量](references/mesh-quality.md) |

## 通用排查顺序

先排除输入错误，再动数值开关，最后才怀疑求解器。优先级从高到低：

1. 几何与网格：负体积、单位（是否应为米却按毫米读入）、包围盒尺寸、区域数量/名称、接口配对、边界层实际厚度。
2. 边界条件与物理：压力/流量口径与单位、参考系、旋向、湍流量初值、介质物性、开口回流、周期/滑移/多相设置的搭配。
3. 数值格式与松弛：先以一阶/低松弛/小步跑通，再逐项放宽；记录每一步改了什么。
4. 求解器与资源：内存、磁盘、依赖 DLL/许可、并行分区、旧缓存或旧场残留。

每阶段完成后独立回读工程，确认修改真的生效。得到稳定结果后，再验证「取消限制、升级格式、细化网格」的敏感性，才能判断该结果是否依赖数值保护，而不是有效解。

## 证据与结论

「跑完」「生成了场」「曲线趋平」都不能单独证明收敛或物理有效。诊断记录至少包含阶段、输入哈希、实际设置、起止步、残差极值、守恒误差、监测量波动、限制触发统计、终止原因和最终场。NaN、未达步数或大守恒失衡的阶段可用于诊断，不能纳入有效结果排名。
